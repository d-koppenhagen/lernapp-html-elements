  1. A page wraps its main article in <div class="content">. Which element best marks the page's main content?

    • <main> richtige Antwort

      <main> marks the page's dominant content and carries the implicit role "main". A page has exactly one <main>, and screen readers offer it as a landmark to jump to.

    • <div id="main">

      A <div> is a generic container with no semantic role, so the id "main" adds no meaning for assistive technology. The region is not announced as a landmark.

    • <section>

      <section> marks a thematic section and needs its own heading. It does not mean "the main content of the page".

    • <article>

      <article> marks a self-contained, independently distributable piece such as a blog post. It is not the wrapper for all of a page's main content.

    <main> is the one element for a page's primary content; it gives a "main" landmark for free, which a <div> never does.

  9. What is the common, recommended convention for the top-level heading of a page?

    • One <h1> that names the whole page richtige Antwort

      A single <h1> gives the page one clear title at the top of the heading hierarchy, which helps users scan the outline. It is a widely recommended convention.

    • An <h1> at the start of every paragraph

      Headings are not paragraph markers; an <h1> per paragraph destroys the outline and overwhelms screen-reader navigation.

    • No heading at all, styled text instead

      Visually styled text that is not a heading gives no structure to assistive technology; the page then has no navigable outline.

    • Several <h1> elements, one per colour theme

      Headings describe structure, not styling. Reusing <h1> for themes is not what heading levels mean.

    A single, descriptive <h1> at the top is the clear, conventional choice; heading levels build the outline, they are not styling hooks.
